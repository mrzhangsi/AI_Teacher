# 电子教官（AI Teacher）

本地运行的学习状态监控工具：定期截屏 + 摄像头拍照，判断你是否在学习，不在则发出告警。

基于 **DeepSeek V4.1 Flash**（`deepseek-flash`，原生支持图像输入）。

---

## 快速开始

**方式一：双击 bat（推荐）**

| 文件 | 作用 |
|---|---|
| `setup.bat` | 首次使用：装依赖、建 `.env`、跑自检 |
| `run_gui.bat` | 启动图形界面 |
| `run_cli.bat` | 启动命令行监控 |
| `test.bat` | 跑端到端自测 |

**方式二：命令行**

```bash
# 1. 安装依赖
uv sync

# 2. 配置 API key
#    PowerShell:  Copy-Item .env.example .env
#    cmd:         copy .env.example .env

# 3. 启动
uv run ai-teacher gui      # 图形界面
uv run ai-teacher start    # 命令行
```

图形界面里填学习目标 → 点「启动监控」，界面会实时显示状态、计时、采样次数、token 消耗和预估花费，底部有运行日志。关窗时会先让监控线程优雅收尾再退出。

## 课堂模式（番茄钟）

每隔一段时间提醒休息，**休息期间完全不抓拍**（不截图、不开摄像头、不调模型）。

**启动方式**

- 图形界面：勾选「课堂模式（定时提醒休息）」，默认 40 分钟专注 + 10 分钟休息，可改
- 命令行：
  ```bash
  uv run ai-teacher pomodoro                  # 查看当前设置
  uv run ai-teacher pomodoro on               # 开启（用默认 40+10）
  uv run ai-teacher pomodoro on --focus 45 --rest 8# 自定义时长
  uv run ai-teacher pomodoro off              # 关闭
  ```

**行为**

- 专注满 40 分钟 → 右下角弹出「该休息一下了」+ 提示音
- 休息 10 分钟 → 界面显示倒计时，状态区变成「休息中」，日志提示「期间不抓拍」
- 休息结束 → 提醒「休息结束，已完成 N 轮专注」，自动回到监控
- 随时点「停止」可立刻退出，不用等休息走完

**为什么值得开**：40 分钟是专注的合理上限，超了就该离开屏幕活动一下。而且休息时**不抓拍**意味着摄像头指示灯熄灭——既省电也不打扰正在休息的你。

报告里会多一组数据：

```
── 课堂模式 ──
 完成轮次    2 轮
 累计休息    20 分钟（期间未抓拍）
```

## 模型判定：为什么必须关闭思考模式

DeepSeek 的 `deepseek-flash` **默认开启思考模式**，而思考链的 token 会计入 `completion_tokens`。曾因为 `max_tokens=48` 导致：

```
finish_reason: 'length'   completion_tokens: 48   reasoning_tokens: 48
模型输出: ''    ← 正文一个字都没输出 → bad_json
```

**48 个 token 全被思考链吃光了。** 实测开思考要 **613 tokens** 才憋出正文；关闭后只要 **14 tokens**，省了 40 多倍。

所以请求里固定带三个参数：

```json
{
  "thinking": {"type": "disabled"},
  "response_format": {"type": "json_object"},
  "max_tokens": 64,
  "detail": "low"
}
```

**两个开关必须一起用**，实测：

| 组合 | think | 输出 | 解析 |
|---|---|---|---|
| 关闭思考 + json_object | 0 | 14 | ✅ |
| 仅关闭思考 | 0 | 12 | ❌ 回单引号，json.loads 解析不了 |
| 仅 json_object | 64 | 空 | ❌ 思考吃光 token |

用 JSON Output 后提示词也必须跟着改：官方要求 prompt 含 `json` 字样并给出格式样例，而且**样例要用双引号**——原来写的 `{'s':0}` 会让模型也回单引号，那样即使关闭思考也解析失败。

## 判定逻辑：只有确认「人不在」才能本地定案

**其余情况一律交给模型看屏幕。** 两条理由：

1. **画面活跃 ≠ 在学习**——打游戏时画面同样剧烈变化，本地规则区分不了
2. **画面固定也可能在思考**——盯着屏幕发呆不代表没在学；反过来，人在屏幕里也可能在看手机

所以本地只保留两个零成本的硬规则：

```
屏幕已锁定              → 分心（零成本）
连续 3 帧确认无人        → 分心（零成本）
其他一切（含人在场）    → 交给模型判断桌面内容
```

这意味着模型调用次数变多，但每次约 270 tokens，单次成本约 ¥0.0003~0.0007。

## 运行中改目标

界面上的「修改当前目标」按钮，**运行中也能点**——不用重启，下一个判定就生效：

```
[事件] 目标已修改 | 刷 LeetCode-> 看机器学习网课
[  3] focusing  模型   正在看网课学习    ← 判定理由已跟着目标变了
```

只改内存值，不动线程、不重置统计、不重建摄像头。空白与重复的目标会被忽略。

## 测试不会用你的 API key

本地 `.env` 里有真实 key 时，测试**依然不会发出任何请求**，靠三层保险：

1. `tests/isolation.py` 在测试代码之前把 `AI_TEACHER_API_KEY` 强制设为空串，并让 `base_url` 指向不可路由地址。pydantic-settings 中进程环境变量优先级高于 `.env`，所以真实 key 读不到。
2. 断言测试进程读到的 key 确实为空，防止有人删掉隔离层。
3. `tests/test_no_network.py` 劫持 `socket.connect`，跑完整套件后断言**出站连接次数为 0**。这是最硬的一层——直接证明没有任何数据包离开本机。

验证结果：e2e 299 项 + GUI 77 项全部通过，出站连接 **0 次**。

> 这一点很重要，因为 GUI 测试的 `_start()` 会真的起一个监控线程。若摄像头检测不到人脸但画面静止（最常见的「安静看书」场景），L0 会返回 SUSPECT 从而走到 L1 判定——**没有隔离层就会用真实 key 真发请求并扣费**。

任务结束时会自动打印本次会话的完整报告，GUI 里则弹出报告窗口：

```
本次学习会话 · 刷 LeetCode
── 采集 ──
 截图次数    50 次
 拍照次数    50 次（失败 0 次）
 平均间隔    48 秒
── 判定 ──
 本地判定    35 次（占 70%，未调 API）
 模型判定    15 次（占 30%）
── 结果 ──
 学习中      33 次
 分心        12 次
 不确定      5 次
 专注比例    66%
 告警次数    2 次
── 成本 ──
 token 消耗  输入 3,750 / 输出 600
 单次平均输入  250 tokens
 预估花费    ¥0.00495
 图片上传量  0.88 MB
```

几个关键口径：

- **截图次数与拍照次数分开算**。摄像头可能被关闭或被占用，两者不一定相等；拍照失败会单独标注。
- **本地判定占比就是省钱效果**。`本地判定 35 次（占 70%）` 表示 70% 的采样在零成本层就被定案，完全没调API。
- **平均间隔**直观反映自适应节奏。样本少于 2 次时不显示——首个采样含摄像头初始化开销，算出来的平均值会严重拉偏。
- **统计存进数据库**（`sessions.stats`），所以 `report` 能查历史会话。旧版本建的会话没有这份统计，`report` 会退回到按 tick 记录聚合，并明确提示。

随时可以查历史：

```bash
uv run ai-teacher history     # 最近 15 次一览
uv run ai-teacher report 3    # 看第 3 次的完整报告
```

## 工作原理：三级漏斗

核心思路是**不要每个 tick 都调 API**。单次调用其实很便宜，但本地规则能同时省下**钱、延迟和误报**——锁屏这类确定性事件，用规则判比让视觉模型看一张黑屏更准更快。

```
L0 本地层 · 零成本，拦掉大部分采样
    锁屏检测 / 摄像头无人脸 / 画面帧差≈0 / 键鼠空闲
    ↓ 存疑样本才继续
L1 视觉模型层 · 截图 + 摄像头合成一张图，只发一次请求
    ↓
L2 决策层 · 连续 N 次才定性，自适应采样间隔
    ↓
    告警（桌面通知 + 提示音）
```

### L0 本地规则（零 API 成本）

| 规则 | 判定 | 依据 |
|---|---|---|
| 屏幕已锁定 | **分心**（立即告警） | Win32 `OpenInputDesktop` 返回 NULL |
| 摄像头画面中无人脸 | **分心**（立即告警） | Haar 级联，约 10ms |
| 长时间无键鼠输入 + 画面静止 | **分心**（立即告警） | `GetLastInputInfo` + 帧差 |
| 人在 + 画面活跃 + 近期有输入 | **学习中**（不调 API） | 上述信号全部为正 |
| 其余（静止阅读、思考、轻微活动） | 交给模型 | — |

### L1 视觉模型层

- **屏幕与摄像头上下拼成一张 JPEG，只发一次请求**。两张图 = 双倍图片 token，合成一张直接砍半；附带好处是模型能同时看到「屏幕上是什么」和「人是什么状态」，判断更一致。
- `detail: "low"` 让服务端先缩到 512×512 再推理，约 **159 tokens/张**。
- 提示词极简（73 字符），不解释规则、不列举例外。
- `temperature=0`、`max_tokens=48`——输出只是个短 JSON。
- 网络异常或解析失败时**保守判为学习中**，不冤枉用户、不打扰。

### L2 状态机

- **抗抖动**：L1 判定分心需**连续 2 次**才告警；L0 硬规则（确定性高）立即告警。
- **启动宽限期** 180 秒，期间不打扰。
- **告警冷却** 300 秒，避免刷屏。
- **自适应间隔**：连续 3 次判定学习中，间隔 45s → 90s → 180s → 300s 封顶；一旦可疑立刻回落到 45s。

## 成本核算

下面是**实测值**（关闭思考模式，连续 12 次采样，零失败、零波动）：

| 项 | tokens |
|---|---|
| 合成图（`detail=low`，服务端缩到 512×512） | ~215 |
| 提示词 | ~61 |
| 输出 JSON | 14 |
| **单次合计** | **276 输入 + 14 输出** |

### 单次花费（分时段）

DeepSeek 的**输出比输入贵 4 倍**，且**高峰时段单价是空闲时段的 2 倍**：

| 时段 | 输入价 | 输出价 | 单次花费 |
|---|---|---|---|
| 空闲 | ¥1/M | ¥4/M | **¥0.000332** |
| **高峰** | ¥2/M | ¥8/M | **¥0.000664** |

**高峰时段** = 周一至周五（不含法定节假日）9:00–12:00、14:00–18:00，**北京时间**。
`ai_teacher.stats.is_peak_time()` 负责判断，`cost` 命令会显示当前时段。

> 注意 `max_tokens` 设成 64 不会多花钱——**按实际用量计费，不是按上限**。

**日成本取决于学习表现**（间隔 60~300s，每天有效学习 8 小时）：

| 场景 | 自适应间隔 | 每天调用 | 空闲日成本 | 高峰日成本 |
|---|---|---|---|---|
| 持续在学（安静读书） | 拉到 300s | 128 次 | ¥0.042 | **¥0.085** |
| 一直分心（打游戏） | 60s（最密） | 480 次 | ¥0.159 | **¥0.319** |

**「越不学习越费钱」是合理的**——判定「你在学」需要密集采样来确认。

想避开高峰时段？**在晚间或周末使用单价直接减半**（空闲时段全天，含周末全天）。

**省钱的三个关键手段**：① 屏幕+摄像头合成一张图；② `detail=low`；③ **关闭思考模式**（这一项省了 40 倍——开思考要 613 tokens，关掉只要 14）。

## 调用预算护栏

`VisionJudge` 内置硬性调用上限（默认 600 次/会话，约等于 10 小时的采样量）。超过后 `judge()` 直接返回 `budget_exceeded`，**不再发出任何 HTTP 请求**，界面显示「已达调用预算，本次不再调用模型」。

为什么要加这个：**调参数时反复实测很容易在不知不觉中发出上百次请求**。加护栏前，一次参数调优就发出了 118 次（约 ¥0.07）。钱不多，但这暴露了一个防护漏洞——测试隔离只保护测试套件，自己写的临时脚本会完全绕过它。

| 字段 | 含义 |
|---|---|
| `total_calls` | 逻辑调用次数（每 tick 最多 +1），用于报告与预算判断 |
| `request_count` | 真实 HTTP 请求数，**含重试**，用于排查实际发出多少请求 |

默认上限 600 远高于正常使用量，正常跑一天（60~300s 自适应间隔）只会在「一直分心」时用到 480 次。如果需要主动放开做实验，可以设环境变量：

```bash
AI_TEACHER_UNLIMITED_CALLS=1 uv run ai-teacher start
```

**调参建议**：不要用真实 key 反复试。先用少量样本确认方向，再用 `uv run ai-teacher start --once` 做单次验证——每个 `--once` 只发 1 次请求。

> **为什么不把图缩得更小？** DeepSeek 会把总像素低于约 544×544 的图**放大**回去。缩到 640 宽已是 token 地板，再缩纯属白干。缩图的意义在于减少 base64 体积和上传带宽（2560×1600 的截图压缩后约 25 KB，而非数 MB），以及降低网络抖动导致的重试率。

## 配置

编辑 `config.toml`（改完重启生效），或用 `goal` 命令改目标。API key 只从 `.env` 读，不会写进配置文件。

### `[capture]` 图像采集

| 键 | 默认 | 说明 |
|---|---|---|
| `compose_width` | 640 | 合成图宽度。影响清晰度与体积 |
| `jpeg_quality` | 60 | JPEG 质量，30~95 |
| `camera_ratio` | 0.28 | 摄像头占宽度比例，判定「人是否在」不需要高分辨率 |
| `camera_index` | 0 | 摄像头设备序号（多摄像头时改） |
| `diff_width` | 160 | 帧差检测的缩略图宽度 |
| `diff_threshold` | 6.0 | 帧差阈值，越小越敏感 |

### `[rules]` 本地规则

| 键 | 默认 | 说明 |
|---|---|---|
| `idle_soft_s` | 180 | 键鼠空闲超过此值，开始降低「学习中」判定权重 |
| `idle_hard_s` | 600 | 空闲超过此值 + 画面静止 → 硬判分心 |
| `face_min_ratio` | 0.02 | 人脸面积占比低于此值认为人不在 |

### `[judge]` 状态机

| 键 | 默认 | 说明 |
|---|---|---|
| `strikes_to_warn` | 2 | 模型判定分心需连续几次才告警 |
| `grace_period_s` | 180 | 启动宽限期 |
| `alert_cooldown_s` | 300 | 两次告警的最小间隔 |
| `interval_min_s` | 60 | 最短采样间隔（分心时用） |
| `interval_max_s` | 300 | 最长采样间隔（持续在学时拉到这） |
| `interval_grow_after` | 2 | 连续几次学习后拉长间隔 |
| `focus_ewma_alpha` | 0.4 | EWMA 平滑系数，越小越看重历史 |
| `focus_healthy_ratio` | 0.7 | EWMA 高于此值判为学习中 |
| `focus_bad_ratio` | 0.4 | EWMA 低于此值判为分心 |

## 隐私

- **图片默认不落盘**，只把判定结果存入 `data/sessions.db`。需要留证据时可自行改 `monitor.py`。
- 摄像头画面是否上传由 `upload_camera` 控制。设为 `false` 时仍会在**本地**做人脸检测（不花钱、不外传），但 API 只能看屏幕。
- `monitor_camera = false` 可完全关闭摄像头。

## 记录查询

所有 tick 存在 `data/sessions.db`（SQLite）：

```sql
SELECT datetime(ts, 'unixepoch', 'localtime') AS 时间,
       l0_verdict AS 本地判定,
       studying AS 是否在学习,
       reason AS 原因,
       interval_s AS 下次间隔
FROM ticks ORDER BY ts DESC LIMIT 20;
```

### GUI 与 CLI 如何共用Monitor

`Monitor` 通过 `on_event` 回调把内部状态广播出来，CLI 不传就只打印到终端，GUI 传了就往队列里塞、由主线程取出来刷新界面。这样避免了两份重复的监控逻辑。

- **监控跑在后台线程**：截图、摄像头、网络都是阻塞操作，放主线程界面会卡死。
- **UI 只在主线程更新**：`root.after` 定时轮询队列。
- **关窗不硬杀线程**：先 `monitor.stop()`，再 `thread.join(timeout=8)`，让数据库和摄像头句柄正常释放。
- **`shutdown()` 幂等**：关窗和线程退出可能各调一次。

## 已知限制

- **仅 Windows**：用了 `GetLastInputInfo` / `OpenInputDesktop` 等 Win32 API。
- **只支持主显示器**：`mss.monitors[1]`。多屏场景需改 `capture.py`。
- **必须锁 OpenCV 4.x**：OpenCV 5.0 移除了 `CascadeClassifier`（Haar 级联），故 `pyproject.toml` 里锁了 `opencv-python-headless<5`。
- 摄像头不可用时（被占用/无设备）自动降级为仅凭屏幕判定。
